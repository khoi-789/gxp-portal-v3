TÀI LIỆU ĐẶC TẢ KỸ THUẬT: GxP PORTAL CORE & SUPABASE INTEGRATION (PILOT)1. MỤC TIÊU DỰ ÁNXây dựng lớp vỏ trung tâm (Core Shell) của hệ thống GxP Portal bằng React/Next.js. Dự án này nhằm mục đích thiết lập kết nối thành công với Supabase (PostgreSQL), kiểm thử tính năng phân quyền (RBAC), render giao diện động (Dynamic App Grid) và quản lý danh mục gốc (Master Data).2. BỘ THƯ VIỆN KỸ THUẬT ĐỒNG NHẤT (UNIFIED TECH STACK)Hệ thống bắt buộc phải khởi tạo package.json với các thư viện sau (không sử dụng thư viện thay thế):Core Framework: react, next (hoặc vite tùy cấu hình AG).UI/UX: antd (Ant Design components), tailwindcss (Styling), lucide-react (Icons).Database & API: @supabase/supabase-js (Kết nối DB), @tanstack/react-query (Fetch & Cache data).Form & Validation: react-hook-form, zod, @hookform/resolvers/zod.Tiện ích (Cài sẵn cho hệ sinh thái): dayjs (Ngày tháng), recharts (Biểu đồ), xlsx (Excel), @react-pdf/renderer (Xuất PDF).3. CẤU TRÚC DATABASE (SUPABASE SCHEMA)Dự án sử dụng cơ sở dữ liệu quan hệ (PostgreSQL). Cấu trúc các bảng cốt lõi như sau:3.1. Bảng users (Quản lý User & Bối cảnh)CộtData Type (Supabase)Ràng buộcMô tảiduuidPrimary KeyID lấy từ Supabase Auth.emailtextNot Null, UniqueEmail nhân viên.full_nametextNot NullTên đầy đủ.department_codetextNot NullMã bộ phận (VD: QA, KHO, SCM, DEV).system_roletextNot NullPhân quyền hệ thống: admin hoặc staff.3.2. Bảng portal_apps (Cấu hình lưới ứng dụng động)CộtData Type (Supabase)Ràng buộcMô tảapp_iduuidPrimary Key, Autoapp_nametextNot NullTên ứng dụng (VD: Khiếu nại CC, BBSC).typetextNot NullChấp nhận 2 giá trị: link hoặc folder.target_urltextNullableĐường dẫn route (VD: /apps/cc). Bỏ trống nếu type là folder.parent_iduuidNullable, FKNếu nằm trong thư mục, trỏ về app_id của thư mục đó.allowed_deptstext[] (Array)Not NullMảng các phòng ban được phép thấy app (VD: {"QA", "KHO"}).is_testingbooleanDefault falseNếu true, UI hiển thị ruy-băng "TESTING MODE".3.3. Bảng master_items (Danh mục Sản phẩm INFOR/SAP)CộtData Type (Supabase)Ràng buộcMô tảitem_codetextPrimary KeyMã từ INFOR/SAP (VD: SA1100013).item_nametextNot NullTên sản phẩm + Hàm lượng + Quy cách.supplier_codetextNot NullMã Hãng/Nhà cung cấp (VD: HYPHENS).visa_notextNullableSố đăng ký lưu hành.is_activebooleanDefault trueTrạng thái kinh doanh.4. KIẾN TRÚC UI/UX & COMPONENTSToàn bộ mã nguồn phải được chia thành các Components rõ ràng để dễ dàng mở rộng theo kiến trúc Micro-Frontends.4.1. Component Lõi: <PortalLayout>Mô tả: Là component bọc ngoài cùng (Wrapper).Thành phần:Top Header: Background xanh mòng két (Teal) chuẩn ngành Y tế. Chứa Logo GxP Portal ở giữa, khung Global Search dạng mờ, góc phải là tên User hiện tại và Icon Setting.Admin Toolbar: Nằm ngay dưới Top Header, background màu vàng/kem nhạt. CHỈ HIỂN THỊ nếu user.system_role === 'admin'. Chứa các nút: "QL Nhóm", "Thêm công cụ mới" (mở Modal quản lý portal_apps).4.2. Component: <AppDashboard> & <AppCard>Mô tả: Lưới hiển thị các ứng dụng. Fetch data từ bảng portal_apps bằng @tanstack/react-query.Logic Phân quyền (RBAC Rendering): Lọc mảng data nhận được: Chỉ render <AppCard> nếu user.department_code tồn tại trong mảng allowed_depts của app đó (hoặc nếu user là admin thì thấy hết).Tương tác (Event Handling):Nếu <AppCard type="link">: Bấm vào gọi hàm chuyển route.Nếu <AppCard type="folder">: Bấm vào sẽ mở <FolderModal>, bôi mờ nền phía sau, trong Modal hiển thị danh sách các AppCard con có parent_id khớp với folder này.Giao diện <AppCard>: Nền trắng kính (Glassmorphism), có Icon góc giữa, Tag phòng ban góc trái trên, và dải ruy-băng đỏ "TESTING MODE" góc phải trên (nếu is_testing === true).4.3. Component: <MasterItemManager>Mô tả: Màn hình CRUD (Thêm/Sửa/Xóa) dành cho Admin quản lý danh mục INFOR/SAP.Giao diện: Dùng <Table> của antd có chức năng Pagination và Search theo item_code.Form Thêm Mới: Khi bấm "Thêm Sản phẩm", mở <Drawer> hoặc <Modal>. Form nhập liệu BẮT BUỘC dùng react-hook-form + zod để Validate (Bắt buộc nhập item_code và item_name).5. YÊU CẦU DỮ LIỆU MẪU (MOCK DATA & SUPABASE SETUP)Trong giai đoạn test này, Antigravity cần thực hiện 2 việc:Tạo file lib/supabase.js để kết nối API (sử dụng biến môi trường NEXT_PUBLIC_SUPABASE_URL và NEXT_PUBLIC_SUPABASE_ANON_KEY).Viết một hàm "Seed Data" (hoặc cung cấp nút "Tạo dữ liệu mẫu") để Insert khoảng:1 User (Admin - QA).4 Portal Apps (1 Folder tên "App Công Ty", 2 App Link thuộc QA/Kho, 1 App có trạng thái Testing).5 Master Items (Sản phẩm).
